# Visual Testing Layer - Architectural Exploration

## Current State

- **Framework & Tech Stack**: Astro v5 (`astro: ^5.0.0`), `@astrojs/check`, `@astrojs/sitemap`, `@astrojs/vercel`, TypeScript 5.7, Node.js 22.
- **Routing & Content Structure**: Dynamic catch-all routing via `src/pages/[...slug].astro`, powered by Astro Content Collections with 50 markdown content files covering core landing pages, localized hub pages (Cancún, Cumbres, Huayacán, Isla Mujeres, etc.), contact, and legal terms.
- **Existing Testing Setup**: Minimal Node test runner (`node --experimental-strip-types --test src/utils/*.test.ts`) for utility functions. No End-to-End (E2E) or visual regression test setup exists.
- **CI/CD State**: No GitHub Actions workflows currently present in `.github/workflows/`. Deployment is handled via Vercel integration.

## Affected Areas

1. **`package.json` & Dependencies**:
   - Add `@playwright/test` to `devDependencies`.
   - Add scripts: `test:visual` (`playwright test`), `test:visual:update` (`playwright test --update-snapshots`), `test:visual:ui` (`playwright test --ui`).
2. **Configuration (`playwright.config.ts`)**:
   - Web server configuration to automatically build (`npm run build`) and preview (`npm run preview`) local static output before running tests.
   - Devices & Viewports definitions for Desktop Chrome, Desktop Safari, Mobile Chrome (Pixel 7), and Mobile Safari (iPhone 14).
3. **Test Suites (`tests/visual/*.spec.ts`)**:
   - E2E visual regression specs covering key page archetypes (Homepage, Service Landing, Location SILO Page, Contact, Legal).
4. **CI/CD Infrastructure (`.github/workflows/visual-testing.yml`)**:
   - New GitHub Actions workflow for PR checks and branch pushes.
   - Dependency installation, Playwright browser caching, test execution, and visual diff artifact uploading on failure.
5. **Version Control (`.gitignore`)**:
   - Ignore `test-results/` and `playwright-report/`.
   - Commit baseline snapshot directories (e.g. `tests/visual/**/*.png`).

## Approaches & Tradeoffs

### Approach 1: `@playwright/test` Native Screenshots against `astro preview` (RECOMMENDED)

- **Mechanism**: Playwright runs against production build preview (`npm run build && npm run preview` at `http://localhost:4321`). Uses Playwright's built-in `toHaveScreenshot()` visual comparison engine across 4 specific device/browser targets:
  - **Desktop Chrome**: Chromium @ 1280x720
  - **Desktop Safari**: WebKit @ 1280x720
  - **Mobile Chrome**: Pixel 7 (412x915, DPR 2.625)
  - **Mobile Safari**: iPhone 14 (390x844, DPR 3)
- **Pros**:
  - Tests actual static HTML/CSS/JS build artifacts generated by Astro v5.
  - Zero external SaaS costs, API keys, or third-party dependencies.
  - WebKit and Chromium are natively managed and cached by Playwright.
  - Out-of-the-box HTML reports and diff artifacts on CI failure.
- **Cons**:
  - Font rendering anti-aliasing can slightly differ across OS environments (Linux CI vs local macOS/Windows). Baselines should be generated/updated in CI environment.

### Approach 2: `@playwright/test` against Dev Server (`astro dev`)

- **Mechanism**: Run visual tests against `astro dev` hot-reloading server.
- **Pros**: Faster iteration speed during local development (skips build step).
- **Cons**: Flaky visual comparisons in CI due to on-demand module compilation, CSS injection delays, and dev server overhead.

### Approach 3: External Cloud SaaS (Percy / Chromatic / Lost Pixel)

- **Mechanism**: Push DOM snapshots to cloud rendering service.
- **Pros**: Hosted UI for visual diff approval workflow.
- **Cons**: Adds vendor lock-in, monthly snapshot limits, external API token management, and unnecessary complexity for this Astro site.

## Recommendation

Proceed with **Approach 1**:
1. Install `@playwright/test` as a dev dependency.
2. Create `playwright.config.ts` configuring Chromium and WebKit for Desktop (1280x720) and Mobile (Pixel 7 and iPhone 14), with `webServer` executing `npm run build && npm run preview`.
3. Create `tests/visual/pages.spec.ts` testing top page archetypes:
   - Home (`/`)
   - Core Service (`/mantenimiento-aires-acondicionados-cancun`)
   - Location SILO (`/mantenimiento-en-cumbres`)
   - Contact (`/contacto`)
4. Create `.github/workflows/visual-testing.yml` to automate visual verification on GitHub Actions.

## Risks & Mitigations

- **Risk: Cross-OS Font/Rendering Flakiness**: Linux CI font rendering may differ from macOS/Windows developers.
  - *Mitigation*: Enable `threshold: 0.2` and `maxDiffPixelRatio: 0.02` in Playwright config, and use GitHub Actions as the source of truth for baseline screenshots.
- **Risk: Dynamic Content / Animation Flakiness**: Animations, lazy-loaded images, or dynamic timestamps causing diff false positives.
  - *Mitigation*: Use `animations: 'disabled'` and set `caret: 'hide'` in Playwright screenshot options, ensuring network idle / DOM settled states before capture.
- **Risk: WebKit Linux Dependencies in CI**: Missing WebKit system libraries on GitHub Actions runner.
  - *Mitigation*: Run `npx playwright install --with-deps` in GitHub Actions workflow step.
